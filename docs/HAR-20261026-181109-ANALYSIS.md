### Hover coupling — fixedscale does not fix gravity

`FallingGravity()` in OKMOD returns the hover-adjusted gravity when Hover isON
(`-0.3` via HoverValue). `SophiaMapGravity()` calls that getter and accepts only
absolute values5..160; smaller values trigger fallback50. With HoverOFF, the
getter can return normal9.8, accepted by the estimator. This source path
explains the observed switch9.8 ->50. It is estimator coupling, **not proof**
that actual effective flight gravity equals either value.

Thus fixedx1.1 does not make HF MAP independent from Hover: the estimated time
and requested horizontal velocity can still change substantially. The capture
has different distances/targets between attempts, so it is not a controlled
same-target A/B test of Hover alone. It does not justify assuming50 or9.8 is a
universal server gravity.
